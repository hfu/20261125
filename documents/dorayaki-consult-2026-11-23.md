# dorayaki セッションとの相談メモ（2026-11-23）

相手: 「Dorayaki Surfel Block codec」（hfu の別セッション）。公開済みの範囲のみ。数字は 2026-11-23 時点（dwg7/dorayaki の main と公開ページ）。
**このメモの内容は、まだデッキとマークダウンに反映していない。hfu のレビュー結果と合わせて反映する。**

## 1. 11-21 以降に進んだこと（公開済み、PR #25〜#31）
- Kawazu のデータを、タイル単位で組み直す方式に差し替え。9メッシュ（約4.76億点、約1.08 km²）→ 約83.9 MB の PMTiles 1本。メッシュの継ぎ目の密度の落ち込み（約12%）が無くなった。stars で配信中。
- デモ: カメラが地面の下に潜る問題の対策、色の補正（`?vivid=`）、ソフトな描画の既定化、ダーク地図（bvmap-nightsky、別リポジトリ dwg7/bvmap）、描画パラメータのパネル、傾けた視点で手前のタイルが欠ける不具合の修正、ズーム補正。
- 以前から: 形式は Surfel Block v6（1スプラット12バイト）＋分類コードの面（クラス別の着色）。MLT 枠の識別子 0xD0/0xD1 は実験用で、公式の割り当てではない。
- 非公開: 別のデータでの調査が1件進行中。スライドには使わない。

## 2. 「まだ分からないこと」の更新
- 広域: まだ作っていない（測ったのは約1 km² まで）。静岡県全体を同じ見積もりで掛けると約0.6 TB だが、谷1つからの外挿で、平野や市街地には当てはまらない。設計上は、タイル単位の並列処理（1,000 km² が約100 CPU 時間、見積もり）。
- 小さな PC: Apple M1 のブラウザで、約690万スプラット（46タイル）、毎秒約50〜56フレーム。視界内の最も近い9タイルだけを読み込む。弱い GPU、スマートフォン、古い PC は未検証。
- **精度: 見た目のための表現で、測量成果の代替ではない。** スプラットへの集約と量子化で情報が落ちる。真値に対する精度評価はしていない。測量機関向けには、必ず添える。

## 3. 測量機関の職員向けの切り口（dorayaki 側の案）
- Who uses it: 今は hfu 一人の実験で、外部の利用者はいない。「使われ方の候補」として示す。
- What for（候補。実証済みではない）: (a) 手持ちの航空レーザ・車載計測の点群を、地図タイルと同じ住所（z/x/y）と配信で公開できるか。(b) 標高タイルでは表せない、橋の下面、張り出し、重なった層を見せられるか。(c) 3D 専用のサーバーを立てず、ブラウザだけで見られるか。
- 見せ方: 「橋の下面」が一番分かりやすい対比。
- How old: 最初のコミットは 2026-11-12。12日間、実験22本（EXPERIMENTS.md の E001〜E022）。
- What is missing: 標準ではない、広域は未検証、小さな PC は未検証、測量精度は未評価。
