# 運用セッション（m3xx-fleet-ops）への依頼：予備機2台への教材投入

宛先: `m3xx-fleet-ops` の運用セッション
依頼元: hfu（2026-11-20）
期限の目安: 2026-11-23まで（講義は2026-11-25、第3コマ）

## 背景

2026-11-25の国家測量研修（第3コマ）で、研修員9名が、研修機11台のうち9台を使う。残り2台（m326、m353）は予備機にする。
2026-11-20の調査で、m326とm353には `~/jica_scripts`（教材）が無いことが分かった（2026-08-20の記録と同じ）。予備機が故障機の代わりになるよう、他の9台と同じ状態にしたい。

対象: **m326、m353** の2台だけ。
参照元（正）: 教材が入っている研修機のうち1台（例: m327）。

## 守ること

- この依頼は、hfuが書き込みを許可したものです。範囲は、下の「やること」だけです。
- 対象は m326 と m353 の `~/jica_scripts` のみ。他の台、他のディレクトリ、設定、パッケージ、サービス、再起動には触れない。
- 共有パスワード、Wi-Fiの鍵、秘密鍵、トークンを、リポジトリ、ログ、メモ、コミットに書かない。
- 教材の中に秘密情報（パスワード、鍵、トークン）が入っていないかを、コピーの前に確認する。入っていたら、コピーせずhfuに聞く。
- 疑問点や想定外の状態は、止まってhfuにこのチャットで確認する。

## やること

1. 参照元（m327など）の `~/jica_scripts` の内容を確認する（ファイル一覧、サイズ、所有者、権限、更新日時）。他の教材入りの台（m328、m332など）と同じ内容か、ハッシュで比較する。台ごとに差があれば、報告して、どれを正とするか確認する。
2. m326とm353で、`~/jica_scripts` が本当に無いことを確認する（別の場所に置かれていないかも見る）。
3. 参照元から m326 と m353 へ、`~/jica_scripts` をコピーする（所有者は `niroku`、権限は参照元と同じ）。
4. コピー後に、参照元とのファイル一覧とハッシュが一致することを確認する。
5. 教材が、他の台と同じ前提で動く状態かを確認する（読み取りのみ）。例: 必要なソフトウェア（Docker、Node、Caddy、Martin）と、タイル用のディレクトリ（`/opt/niroku`）が、教材入りの台と同じ状態か。違いがあれば、直さずに、違いを報告する。
6. 教材を実行する試験はしない。実行が必要なら、hfuに確認する。

## 返してほしい形

- m326とm353それぞれについて、コピー前後の状態（`~/jica_scripts` の有無、ファイル数、ハッシュの一致）を、短い表で。
- 手順5で見つけた、他の台との違い（なければ「なし」）。
- 行った書き込みの一覧（何を、どこへ）。これ以外の変更は、していないことの確認。

## 参考

- IPは `192.168.86.<ホスト名の下2桁>`（m326→.26、m353→.53）。2026-11-20の調査で、変化がないことを確認済み。
- SSID・パスワードは、この依頼には関係しない（チャット返信にも書かなくてよい）。
