# 運用セッション（m3xx-fleet-ops）への調査依頼

宛先: `m3xx-fleet-ops` の運用セッション（SSH鍵とCloudflare Accessの権限を持つ側）
依頼元: hfu（2026-11-19）。スライド作成側のセッションは、フリートにもLANにも届かないため、この調査を直接できない。

## 目的

2026-11-25の国家測量研修、第3コマで使う資料に、次の3点を実測値で入れる。

1. 研修機11台（m326、m327、m328、m332、m334、m336、m347、m348、m349、m353、m355）の、現在のIPアドレス
2. 研修機がぶら下がっているWi-FiのSSID（研修員のPCを、このWi-Fiに切り替えてもらう）
3. そのWi-Fiのパスワード（hfuは、スライドへの記載を許可済み。残すかどうかはレビューで判断する）

## 守ること

- **読み取りのみ。** 設定変更、再起動、更新、ファイルの書き込みはしない。
- Wi-Fiのパスワードは、**このチャットの返信にだけ書く。** リポジトリ、ログ、メモ、コミットに残さない（`CLAUDE.md` の規則）。
- SSH接続にはタイムアウトを付ける。pingスイープは、個々のタイムアウトを短くしすぎない（偽陰性を避ける）。
- 応答しない機体は、個別に再確認してから「応答なし」と記録する。
- 疑問点は、hfuにこのチャットで確認する。

## 調べてほしいこと

### A. 各研修機（11台）

| 項目 | 例（読み取りのみのコマンド） |
|---|---|
| ホスト名 | `hostname` |
| 現在のIPv4（Wi-Fiインターフェース） | `ip -4 -br addr show wlan0` |
| 接続中のSSID | `nmcli -t -f active,ssid dev wifi` または `iwgetid -r` |
| 電波の強さ | `nmcli -f IN-USE,SSID,SIGNAL dev wifi` |
| IPが固定か（DHCP予約か） | NetworkManagerの接続設定のIP方式、ルーターのDHCP予約の有無（確認できる範囲で） |
| 教材の有無 | `test -d ~/jica_scripts && echo あり \|\| echo なし`（2026-08-20時点で m326 と m353 は「なし」だった） |

### B. Wi-Fiそのもの

- SSID（全機で同じか）
- 帯域（2.4GHz／5GHz）。研修員のPCが接続できる帯域か
- パスワード: 機体のNetworkManager接続設定から読む。例: `sudo nmcli -s -g 802-11-wireless-security.psk connection show "<接続名>"`
  - 読むだけで、設定は変えない。
- このWi-Fiがインターネットに出られるか（`timeout 8 curl -sI https://example.com` など）。出られない場合、研修員のPCは、切り替えるとインターネットを使えなくなる。
- クライアント分離（AP isolation）が有効か。研修員のPC同士、PCからRPiへ通信できるか。LAN内の別のホストから、研修機へSSH・HTTPで届くか。

### C. 名前解決（研修員のPCはWindows。過去にPowerShellでmDNSが解決しなかった事例がある）

LAN内のホストから、次を試し、結果を記録する。

- `m326.local`（mDNS）が解決するか。研修機の `avahi-daemon` が動いているか。
- `m326.lan`（ルーターのDHCP由来のDNS名）が解決するか。リポジトリの記録では、`m3xx.lan` の逆引きはできている。順引きできれば、`.local` の代わりに使える可能性がある。
- 可能なら、Windows 10/11のPCから `ping m326.local`、`ping m326.lan`、`Resolve-DnsName m326.local` の結果を、hfuに見てもらう。

## 返してほしい形

次の表をチャットに返す。研修機は11行、`m331` と `m342` は載せない。

| ホスト名 | 現在のIP | 前回（2026-08-20）から変化 | SSID | jica_scripts | 応答 |
|---|---|---|---|---|---|

その後に、B（Wi-Fiの性質）とC（名前解決）の結果を、短い文で書く。パスワードは、最後に別行で書く。
