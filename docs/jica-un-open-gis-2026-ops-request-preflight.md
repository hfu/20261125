# 運用セッション（m3xx-fleet-ops）への依頼: 第3コマ前の確認（読み取りのみ）

依頼元: hfu（2026-11-21）。スライド作成側のセッションは、フリートにも管理経路にも接続しない（本リポジトリの規則）。
下の確認を、運用セッションまたは実機に入れる環境で実行し、結果の表を hfu に渡してほしい。

## 目的

2026-11-25 の第3コマ（研修員が自分のPCで Wi-Fi に接続し、`ssh niroku@<IP>` で研修機に入り、ブラウザで `http://<IP>/` を開く）が、
当日に止まりそうな点を、事前に潰す。資料の手順は `src/data.js` のスライド21・25・27を参照。

## 守ること

- **読み取りのみ。** 設定変更、再起動、更新、ファイルの書き込み、パスワード変更はしない。
- パスワードの値は、リポジトリにも、この依頼への返信にも書かない。
- SSH接続にはタイムアウトを付ける。応答しない機体は個別に再確認してから「応答なし」と記録する。
- 対象は研修機11台（m326、m327、m328、m332、m334、m336、m347、m348、m349、m353、m355）。講師専用機・未参加機は対象外。
- 変更が必要だと分かった点は、実行せず、案と理由を書いて返す。

## 確認項目

### A. 初回ログインで止まる要因（最優先）
1. `niroku` のパスワードが期限切れ・変更要求になっていないか（`chage -l niroku` 相当の読み取り）。変更要求が出ると、初回ログインで「新しいパスワードを求められる」状態になり、非IT の研修員は進めない。
2. sshd がパスワード認証を許可しているか。資格情報なしで、認証方式の一覧だけ確認する（`ssh -o PreferredAuthentications=none -o ConnectTimeout=5 niroku@<IP>` が返す一覧）。11台すべて。
3. 失敗回数の上限などの設定（`sshd -T` の `maxauthtries`、`maxstartups`、`logingracetime`、`usedns`）。1台でよい。
4. ログイン直後に表示される内容（バナー、motd、プロンプトの形）。スライド27の手順6「Raspberry Pi のシェルが見える」の文言に使う。パスワード等は伏せる。

### B. ブラウザ手順（`http://<IP>/` で 404）
5. ポート80で応答しているプロセスは何か（`ss -ltnp` 相当）。スライドは「404でOK」としている。
6. そのプロセスは、再起動後も自動で起動するか（サービスの enabled 状態）。運用記録に「`caddy` は disabled」とあるため、80番を誰が提供しているか不明。
7. ポート8000、3000など、教材が使う他のポートの応答（スライド26は「80や8000」と書いている）。
8. ルート `/` に何も無い理由と、表示用の簡単なページを置く案（実行はしない。案と、機体を変更する範囲だけ書く）。

### C. IP と LAN
9. 研修機のIPは、固定割当（機体側）か DHCP か。DHCP なら、ルーター側の予約か（分かる範囲で）。スライド25のIPが当日も変わらないかを知りたい。
10. 各機体の無線の状態（周波数帯、チャネル、信号強度。`iw dev wlan0 link` 相当）。5GHz のみとしているが、弱い機体がないか。
11. 同じSSIDで接続するPCは最大で約10台（研修員9名＋講師）。AP/ルーターの同時接続数に問題がないか、分かる範囲で。

### D. 名前解決（任意）
12. `m327.lan` と `m327.local` を、LAN内の別ホストから解決して結果を記録する（前回は m326 のみ）。

## 返してほしい形

項目番号ごとの結果の表。11台で差があるものは、機体ごとに書く。変更が必要だと思った点は、「案」の欄に書く。
